# 2026-07-27 — `pre-push`'s memory-absent skip warns instead of staying silent when the gitlink it is about to publish is unpublished

The D11 corollary exits 0 without pushing memory when `memory/.git` is absent, so a session-less worktree never blocks the parent push. That branch also fires when memory *is* initialized in this clone and its pinned commit sits ahead of the memory remote — the parent then publishes a gitlink no clone can resolve, silently, which is the failure NFR 2 exists to prevent and which the tier loop thirty lines below already refuses on identical reasoning ("a tier that silently stops publishing is indistinguishable from one with nothing to say"). The skip stays non-blocking; it just stopped being unconditionally silent. The discrimination is local and needs no fetch: no module store means memory was never initialized here, so nothing local can be ahead; a committed gitlink already reachable from the store's `refs/remotes/origin/live` is published. Everything else warns — no gitlink in HEAD, no remote-tracking ref, an unreadable store — because the check cannot answer its own question and an unpublished gitlink is the costlier miss. The store path comes off `--git-common-dir`, not `--git-path`: `modules/` is shared across worktrees but `--git-path modules/x` resolves against the *per-worktree* gitdir and yields `.git/worktrees/<wt>/modules/x`, which never exists — the first implementation used it and read every linked worktree as a fresh clone, staying silent in exactly the case the check exists for. Three cases pinned in `tests/pre_push_hook.bats`; the two silence cases passed before the fix as well, so both were mutation-checked against an unconditional warning. Replaces a memory file that existed only to compensate for the silence.
