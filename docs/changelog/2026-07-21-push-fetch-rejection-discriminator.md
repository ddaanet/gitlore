# 2026-07-21 — Push/fetch-rejection discriminator pinned — and a dead divergence arm found by pinning it

The three sites that route on git's parenthesized rejection reason (`resolve.sh` `push . HEAD:live`, `pre-push` `push origin live`, `session-start.sh` `fetch origin live:live`) now have a suite that provokes each rejection against a real git rather than asserting a hand-written string: stale-ref push → `(fetch first)`, known-diverged push → `(non-fast-forward)`, local `push .` → divergence, ff-only fetch → `(non-fast-forward)`, and a `pre-receive` decline → **not** divergence, plus an end-to-end check that `pre-push` surfaces git's own policy text and leaves no `refs/gitlore/pending` behind. A last case greps the three sites so the mirrored pattern cannot drift from the code it stands for. Pinning it exposed a live bug: **`fetch -q` prints nothing at all on a non-fast-forward** — it only exits 1 — where `push -q` still reports its reason. The tier fetch used `-q`, so its divergence arm was unreachable and a tier that had stopped propagating was reported as merely "stale" with `git said:` trailing into empty space. `-q` dropped (output is captured either way). The bug survived a suite that already tested ff-only rejection because that test ran its own `git fetch` without `-q` — the invocation was the bug, not the logic — so the regression test drives `session-start.sh` and asserts the `systemMessage`, and was confirmed to fail against the `-q` version before landing.
