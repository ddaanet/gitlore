# 2026-08-14 — Direct hook wiring refuses instead of silently appending after an existing `exec` (D25)

Found while mounting the shared `ddaanet` tier into `claude-plugin-dev`: an existing `.git/hooks/pre-commit` there read `#!/bin/sh` / `exec just precommit`, and `wire-direct.sh` appended its own managed block after it. `exec` replaces the process, so the appended block was unreachable — the commit succeeded, the project's own gate ran, and `gitlore_sync_memory_to_live` never fired. A parent commit landed recording the memory gitlink at its pre-migration SHA, with an entire migration left uncommitted in the submodule worktree. Nothing at install time or commit time warned; `pre-push` had no pre-existing content there, so the push path looked correct while the commit path was silently dead.

`wire-direct.sh` now scans an existing hook body for a line whose first token is `exec` before appending, and refuses instead of appending — printing the conflicting file and the line to interpose manually to stderr, then exiting 1. The installer cannot assume it may rewrite the existing hook body to interpose safely, since the project's own gate lives there and must survive; refusing rather than guessing at an insertion point is the safer failure mode, and a false positive (an `exec` inside a string, or a conditional branch that never runs) costs a refused install rather than a silent miss. Both `scripts/install/run.sh` and the `SessionStart` sentinel replay call `wire-direct.sh` unguarded under `set -euo pipefail`, matching the exit-1-when-unsafe precedent `wire-lefthook.sh` already sets, so the refusal aborts the caller instead of leaving a half-wired repo.

`tests/hook_manager_wire.bats` gained a case seeding a pre-commit hook ending in `exec just precommit`, watched red against the unmodified script (appended silently, exited 0) before the fix.

The brief's second defect — composition reverting an incoming tier merge by mirroring root's wording down over a merged carrier — remains open.
