# 2026-06-18 — Trimmed the standing SessionStart `additionalContext` (refines D12) — prohibition up-front, procedure just-in-time

Front-loading the four-step persist *procedure* (summarize → approval → write magic file → commit parent) distorted behavior: a recipe resident in context reads as "a process you must run," so the agent ran ceremony — pausing for explicit user approval *before even writing a memory file* — when memory persistence is meant to be seamless (observed repeatedly downstream). Split the two disclosures by their timing needs: the **prohibition** ("never commit inside the submodule") stays in the always-on context because it guards an action the agent would otherwise take unprompted; the **procedure** is dropped from SessionStart and left to its just-in-time surfaces — the `memory-pre-commit` hook's own output when a direct commit is blocked, and `/gitlore:resolve` on divergence. SessionStart now carries the prohibition plus a one-line seamless happy path (commit the parent; the hook does the rest), which defuses over-worry rather than feeding it. `session-start.sh` `protocol_ctx` trimmed; `cc_hook_session_start.bats` asserts the prohibition + happy path present and the procedure ceremony absent. No change to the gate, approval semantics, or FR11.
