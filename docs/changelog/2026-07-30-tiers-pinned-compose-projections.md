# 2026-07-30 — Tiers are pinned at the gitlink, composition is two projections, and `/gitlore:merge` is the taking half

`SessionStart` fast-forwarded every tier and checked it out at `live`, so a tier routinely outran the gitlink root's index agreed with. Once both had moved, nothing merged them: composition applied its precedence rule and reverted upstream, while the resolver reported `state is healthy` because the tier and its remote agreed. It also left `memory/` dirty — a moved gitlink reads as ` M <tier>` — which made the *next* session skip root's own `merge --ff-only live`. A tier fast-forward suppressed root's. Observed on 2026-07-29 during the `/gitlore:push` dogfood: a local index compaction and an upstream trigger addition had moved the same line, the merge sub-agent resolved it correctly in the tier, and the continuation's compose then replaced the result with root's text.

The fix is to stop the tier from moving on its own. One memory commit records `MEMORY.md` and the tier gitlink together, so root's tier block and the carrier are consistent by construction — and staying that way is a matter of checking the tier out at its recorded gitlink and never fast-forwarding it. `submodule update --init` runs on every session, not only when a tier was never materialized, because every clone made before this already sits ahead. The fetch stays but goes read-only, purely so an upstream-ahead or diverged tier can be *named*; ancestry against `FETCH_HEAD` replaces the old non-fast-forward discriminator, since a fetch that attempts no ref update is refused for nothing. The prepared-merge check moved ahead of the checkout: `submodule update` runs `git checkout`, which unlinks `MERGE_HEAD` silently.

With tiers pinned, composition had nothing left to merge. It had been carrying a degraded copy of the entry-wise merge — the same path-keyed presence rule, but a base that kept only paths and discarded the text, so no per-entry three-way was left to run and root's text won unconditionally. It becomes two projections: **down** in-session (root's active tier lines into each carrier) and **up** once, at the tier-adoption step of a landed merge, where the merged carrier becomes root's block. The three-way stays in `scripts/lib/index-merge.sh`, where the base is real. `refs/gitlore/compose-base` and its audit chain went with the merge they served.

A carrier path root's working tree lacks is disambiguated by **root at `HEAD`**: present there means root deleted the line, absent means nobody authored it in root — so it is kept and reported, never silently destroyed. The cost, accepted: a line added and deleted inside one uncommitted window reads as never-authored and lingers in the carrier until someone acts on the report. Two rules fell out of building it. Root holding *no* line for an active tier states nothing about that tier, so the down projection skips it and the layout adopts its carrier — one rule covering a fresh mount, a deactivate/reactivate round trip, and an emptied block. And the continuation's whole-tree `compose … up` turned out never to have staged root's write at all (it ran `git add -A` in the *tier*), which is why it now stages the root index in the memory store, and compares store against memory root by inode rather than by string: the state file records an absolute path while `memroot` is the submodule path as `.gitmodules` spells it.

Pinning removed the only mechanism that took upstream facts, so `/gitlore:merge` supplies it: publish nothing, take everything. Per store it classifies by ancestry — already-contained is nothing to do, strictly-ahead is a fast-forward plus adoption with no sub-agent (a synthesis on a fast-forward would make taking facts expensive enough to skip), diverged prepares a merge marked `publish: "no"` so the continuation stops after the local `HEAD:live` fast-forward. The mark rides the state file rather than being inferred at continuation time, when the entry point that had the intent is gone. A dirty store is refused rather than checked out over.

Test movement is where the model change is legible. `a dormant tier still receives mirror-down` was deleted — mount augments the root index and unmount purges it, so a root line naming a dormant tier has no legitimate provenance to rescue — and replaced by the property the old base got wrong: a dormant carrier survives two consecutive passes untouched. The two upstream-arrival cases became adoption cases, including the one nothing covered before: root and carrier holding different text for one path, where adoption puts the *carrier's* text in root. Five audit-chain cases went with the ref. The deletion cases now commit the memory store first, which is what makes the omission a deletion rather than a line root never had.
