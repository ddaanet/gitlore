# 2026-07-23 — Two routing-key advisories ride the index→frontmatter sync — and the obvious version of the check was refuted first

The index one-liner feeds CC's recall classifier *and* is copied over the file's `description:`, so a hook with no trigger degrades both surfaces silently. The literal reading — score each hook against its body's distinctive tokens, tf-idf style — was prototyped and **killed on the real store**: at 76 documents `df ≤ 3` marks ordinary prose as distinctive, so the score tracks hook *length*, not quality (`reference` 2.06 vs `feedback` 1.76 — no separation; a hook carrying `GIT_*` and `GIT_INDEX_FILE` scored 0/10). What survives is two countable things. **Byte budget**: the blob loads verbatim, so cost is bytes not lines and the five longest lines are ~a fifth of it; past 80% of 25600 bytes the pass names the percentage and the worst offenders — arithmetic, no false positives. **Missing trigger token**, gated on `metadata.type`: a `reference` fact is reached by an error string or a flag, a `feedback` rule by topic where prose is correct. The gate is what makes it usable — ungated it fires on 22 of 76 bullets, type-conditioned on **3 of 37**, all three worth rewriting. Both **report, never refuse** (`PostToolBatch` cannot undo the write) and are **diff-keyed like the sync**, so a thin old hook does not re-report on every unrelated edit; the token check runs *before* the fill-if-empty bail, since a line whose frontmatter the sync declines to touch is still the routing key. Detection is word-at-a-time in awk, not one ERE — ERE word boundaries are not portable, and splitting on whitespace keeps `well-known` prose while `--flag` is a flag. The third failure mode, a trigger *buried* in a 1.2 KB line, is semantic and stays with the agent. 17 cases in `tests/index_sync.bats`; both new assertions mutation-checked.
