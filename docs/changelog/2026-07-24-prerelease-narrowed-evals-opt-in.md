# 2026-07-24 — `prerelease` narrowed back to plain `precommit`; the evals are opt-in, run by name

The day before (2026-07-23 below), `release` gained a mandatory `prerelease` dependency and gitlore satisfied it with the `prerelease: precommit evals` it already had — putting a 5-round grid that drives the real `claude` CLI on the path of every release, immediately before the one irreversible step. Most releases touch nothing an eval covers, so most of that spend bought nothing, and the cost is real time and real money rather than CPU. `prerelease: precommit` now — the "most plugins" default the toolkit's own docs describe — and `just evals` is called by name. The trigger moves from the release to the change: run the grid before a release that touches an eval-covered flow, and whenever a prompt changes, since a prompt has no assertion-level test and the eval is its only regression check. The 2026-07-23 fix stands on its own terms: the hole it closed was `release` skipping a gate the consumer had declared, and a consumer declaring a narrower gate is that mechanism working, not being reverted. `ddaa:preflight` probes `just precommit` and therefore stays fast. Naming was considered and left alone: `nightly` is the recognized term for the slow tier but names a clock trigger this has none of, and `acceptance` names the test kind rather than the moment — `precommit`/`prerelease` name the trigger honestly.
